# LY-Route 配置表达模型

## 1. 目标

网络配置不得依赖含义模糊的自由文本。API、持久化、编译器和 UI 使用同一套类型化表达，支持成熟网关/策略产品所需的任意值、单值、网段、连续范围和对象引用。

## 2. 地址匹配

规范模型：

```json
{ "kind": "any" }
{ "kind": "host", "value": "192.168.1.10" }
{ "kind": "prefix", "value": "192.168.1.0/24" }
{ "kind": "range", "start": "192.168.1.10", "end": "192.168.1.20" }
{ "kind": "ip_group", "ref": "office-clients" }
{ "kind": "domain_group", "ref": "video-domains" }
```

要求：

- `any` 必须显式保存，不能用空字符串、缺字段或 `0.0.0.0/0` 混用表达。
- `host`、`prefix`、`range` 同时支持 IPv4/IPv6，但起止地址必须同族且 `start <= end`。
- CIDR 保存为网络规范形式；主机位不为零时 UI 必须提示规范化结果，不能静默改变用户意图。
- 范围不能跨地址族；编译器可按后端能力直接使用范围或确定性拆分为最小 CIDR 集合，并在预览中显示展开结果和规模。
- 对象引用使用稳定 ID，不保存显示名称；响应同时提供名称用于展示。
- 域名组只允许进入确有 DNS 跟踪、L7/域名策略或明确解析语义的 Gateway 资源，不得伪装成普通 L3 地址匹配。

## 3. 对象组

IP 组成员支持主机、CIDR、连续范围及受控嵌套 IP 组。域名组支持精确域名、后缀域名和明确的通配规则；不接受 URL、协议或路径。

对象组必须具备：名称唯一性、稳定 ID、备注、成员去重、规范化预览、批量导入/导出、逐行错误、引用列表、循环检测、规模限制、编译展开和删除保护。对象修改后，引用它的策略标记为待重新编译，不得静默保持旧运行态。

## 4. 端口、协议和其他条件

- 端口：`any`、单端口、连续范围、端口/服务组；范围为 `1-65535` 且起点不大于终点。
- 协议：`any`、TCP、UDP、TCP+UDP、ICMP/ICMPv6，以及产品明确支持的协议集合。
- 接口/出口：使用稳定引用选择 LAN、WAN、WAN 组或代理出口，不手填内部 ID。代理订阅出口还必须携带节点选择模式 `fixed_node` 或 `fastest_node`；固定模式引用稳定节点 ID，最快模式引用订阅/候选集合而不是某次探测出的临时节点。

## WAN 组、代理节点与 QoS 类型

- WAN 组 `mode` 只允许 `primary_backup`、`weighted`、`five_tuple`。成员只能引用真实 WAN；代理逻辑 WAN 在 schema、API、导入和 UI 四层均被拒绝。
- `primary_backup` 成员带唯一优先级；`weighted` 成员带正整数权重；`five_tuple` 使用稳定组 ID、成员 ID 与五元组散列，不把瞬时计数器作为散列输入。
- 代理策略出口使用带判别字段的类型：`fixed_node` 必须引用订阅展开后的稳定节点；`fastest_node` 必须配置健康候选集，并保存当前选择、探测时间、滚动延迟、失败原因和切换原因。节点密码、订阅正文和探测密钥不得进入审计或普通日志。
- 用户限速与内置智能 QoS 是两个独立意图。用户限速保存明确的匹配条件和上/下行速率；智能 QoS 只保存启用状态、线路带宽来源/结果和只读运行指标，底层算法参数不进入用户可编辑 schema。

## DNS 决策与 TTL 选线绑定

- DNS 规则具有稳定 ID、显式顺序、源客户端选择器和精确域名/后缀/域名组选择器，采用首匹配停止。
- DNS 动作是带判别字段的 `resolve_via`、`fixed_answer` 或 `nodata`。`resolve_via` 引用固定 WAN、固定上游或代理出口；不允许普通 NAT、路由或下一跳字段。
- TCP/UDP 53 默认接管是 Gateway 运行时系统意图，不由用户通过添加 `any` 规则才能生效，也不能被普通 PBR 覆盖。
- 解析结果生成 `{client_scope, domain, answer_ip, dns_egress_id, expires_at}` 形式的运行时绑定；业务选路在 TTL 内先查该绑定，再查普通策略路由。到期、规则删除、上游切换和缓存失效必须原子清理。
- 未命中和命中线路不可用都产生显式 NODATA/失败状态；schema 不提供隐式默认上游、低规则回退或普通路由回退开关。
- 时间：`any` 或时间计划引用。
- 策略组：公共条件在组级定义，组内规则继承并只填写差异；顺序和优先级可调整且有冲突预览。

## 5. 资源适用矩阵

| 资源 | any | 主机/CIDR | 连续范围 | IP 组 | 域名组 |
| --- | --- | --- | --- | --- | --- |
| Gateway 路由/安全/流控匹配 | 是 | 是 | 是 | 是 | 仅语义支持时 |
| Gateway DNS 策略源地址 | 是 | 是 | 是 | 是 | 不适用 |
| Gateway DNS/域名路由目标 | 是 | 不作为域名 | 不适用 | 不适用 | 是 |
| WAN/LAN 接口自身地址 | 否 | 仅主机前缀 | 否 | 否 | 否 |
| DHCP 地址池 | 否 | 可由 CIDR 派生 | 是 | 否 | 否 |
| NAT/端口映射匹配条件 | 是 | 是 | 是 | 是 | 仅明确支持时 |
| NAT 转换地址/内部主机 | 否 | 单地址或接口地址 | 按资源约束 | 否 | 否 |
| Orchestrator 策略匹配 | 是 | 是 | 是 | 是 | 否 |

## 6. 兼容和迁移

现有 `src_ip`、`dst_ip`、空字符串和对象名称字符串必须通过版本化迁移转换为类型化模型。无法无歧义识别的旧值进入“需要人工确认”，不得猜测后直接下发。API 可在过渡期读取旧字段，但新写入只接受规范模型，OpenAPI、导入导出和审计都使用同一结构。

## 7. 验收

- API 契约对每种合法类型有正例，对空字符串伪 `any`、反向范围、跨族范围、坏 CIDR、悬空引用和循环引用有反例。
- UI 选择对象后提交稳定 `ref`，重命名对象不破坏策略。
- 编译预览显示范围展开、对象展开、最终匹配条件和资源规模。
- 删除被引用对象返回引用清单；批量导入返回准确行号和原因。
- 保存、导出、导入、重启、应用和回读后语义保持一致。
