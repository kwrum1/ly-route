# LY-Route UI 产品重构基线

> 本文件的旧“页面位置冻结”规则已废止。整体重构的执行蓝图见[产品 UI 重构蓝图](ui-rearchitecture-plan.md)。

## 1. 目标

本轮 UI 工作以真实设备可观测数据、成熟的网络策略操作模型和表单易用性为主。Gateway 与 Orchestrator 都可以重构菜单、概况及页面内容，但必须遵守产品边界和 API 回读约束：

- Gateway 以运行概览、网络与出口、策略与对象、系统维护组织页面；旧入口仅在有真实功能替代时迁移或合并。
- Orchestrator 保留首页中流量概况、系统概况、在线用户和 Top 连接的位置，删除 Top 域名；把原 LAN/WAN 功能改为“编排设置”，并放在“网卡设置”之后、“流量编排”之前。
- 可以按产品对象模型重组页面和操作层级；不得丢失已有可用能力，且迁移后必须有明确入口。
- 参考 iKuai 4.0 的浅蓝白视觉、白色主内容面、轻边框、清晰状态色和现代控件质感。
- 重点改造当前粗糙的 WAN 创建、策略创建、对象选择、表格、弹窗和错误提示样式。
- Panabit 只用于研究成熟网络配置语义与表单交互，不复制其视觉、代码或资产。

任何位置调整只允许用于修复错位、遮挡、间距、响应式溢出或可访问性问题，不得改变用户已经熟悉的内容顺序和操作路径。

## 3. 布局与迁移规则

- Gateway 与 Orchestrator 的导航、首页、表格列和编辑器均可调整，以减少跨页操作和暴露真实运行状态为目标。
- 用户熟悉的能力必须保留等价入口；不属于目标产品的入口必须删除，不能以隐藏或禁用状态长期保留。
- 编辑器可按基础信息、匹配条件、动作/路径、运行保护分区；字段调整必须维持 API 契约和保存回读。
- 可以统一宽度、高度、对齐、留白、标签位置、必填标识、帮助文字和错误文字。
- 新增成熟配置能力时，在原字段位置将自由文本升级为类型化选择器，或在相邻位置增加对象选择、格式切换和预览，不重排其他字段。

## 4. 视觉样式

- 页面背景使用低饱和浅灰蓝，主内容面和弹窗使用白色。
- 主按钮使用统一蓝色；次操作、危险操作、禁用和加载状态必须清晰区分。
- 表格统一表头、行高、斑马/悬停、选中、排序、筛选、空态和分页样式。
- 表单统一标签、输入框、选择器、多选、文本域、掩码/单位后缀、校验和帮助信息。
- WAN 创建等长表单保持当前字段位置，但使用分区边框、稳定栅格、对齐的标签和值、紧邻字段的错误提示和底部固定操作区改善观感。
- 弹窗统一标题、内容滚动、关闭、取消/保存顺序、危险确认和提交中状态，禁止内容抖动或按钮漂移。
- 所有字体、图标和图表资源离线提供；颜色不能成为唯一状态表达。

## 5. 成熟配置控件

地址匹配字段统一升级为一个类型化控件，在原位置支持：

- `任意（any）`
- 单个 IPv4/IPv6
- CIDR，如 `192.168.1.0/24`
- 连续范围，如 `192.168.1.10-192.168.1.20`
- IP 组引用
- 在产品和策略语义允许时引用域名组

控件必须提供类型选择、自动补全、对象搜索、创建对象快捷入口、格式即时校验、规范化预览和引用使用情况。`any` 是显式值，不能再用空字符串暗示。详细语义见[配置表达模型](configuration-model.md)。

端口字段同样支持 `any`、单端口、连续范围和端口/服务组；协议、接口、WAN/WAN 组、时间计划等使用可搜索选择器，不要求用户记忆内部 ID。

## 6. 产品边界

- Gateway 可以在路由、安全、流控、DNS 等适用策略中使用 IP 组和域名组。
- WAN/LAN 接口自身地址只能是合法主机地址/前缀，不能使用 `any`、IP 组、域名组或连续范围。
- DHCP 地址池使用起止范围或由网段派生的范围，不使用域名组。
- Orchestrator 使用 `any`、单 IP、CIDR、连续范围和 IP 组；按现有产品边界不引入域名组。若要改变此边界必须另行确认。
- Orchestrator 首页“流量概况”只统计 WAN/LAN 边界和各编排组流量；“在线用户”来自 VPP 邻居观测，“Top 连接”来自 VPP 连接观测，不得读取 DHCP 租约、DNS 或 NAT 状态；删除 Top 域名。
- Orchestrator 目标菜单为：流量概况、系统概况、在线用户、Top 连接、网卡设置、编排设置、流量编排、流量控制、安全控制、IP 管理、系统用户管理、配置管理。
- “网卡设置”先配置唯一 LAN/WAN（物理口或聚合组）；“编排设置”只从剩余未占用物理口中选择严格两个端口，并明确接 LAN/接 WAN 方向；“流量编排”使用可拖动策略组和组内序号，未命中默认直达 LAN。
- Orchestrator 不显示 WAN 群组、路由/NAT、端口映射、DNS 管控、DHCP 服务、域名管理、代理或 Top 域名入口。
- Gateway 策略路由选择订阅代理时，在原字段位置显示“固定节点/最快节点”模式。固定节点使用可搜索节点选择器；最快节点显示当前节点、滚动 ping、可用性、上次切换原因和探测时间，不暴露内部滞回参数。
- WAN 组模式只显示主备、加权负载和五元组负载，并在前端直接禁止选择代理逻辑 WAN。
- QoS 页面明确分为“策略限速”和“智能 QoS”两个区块。智能 QoS 只显示启用状态、线路带宽、满载延迟和运行健康，不允许修改内部 CAKE/SQM 类算法参数。
- DNS 页面在原有位置明确展示“默认接管 TCP/UDP 53”和不可被普通策略路由覆盖的优先级。规则编辑器只提供选线/上游/代理解析、固定应答和 NODATA，不混入 NAT/普通路由字段；运行状态显示命中规则、实际出口、上游、TTL 绑定、失败原因和是否发生外部 DNS 绕过拦截。
- UI 不得展示后端或数据面不能准确执行的选项。

## 7. 验收

- 使用现有页面截图做前后对照，证明内容位置和操作路径未发生业务性变化。
- 视口覆盖 1440×900、1280×800、1024×768、390×844；只允许响应式折叠解决窄屏问题。
- Gateway WAN 创建以及路由、安全、流控、DNS 策略至少覆盖 `any`、主机、CIDR、范围、IP 组和域名组适用场景。
- Orchestrator 策略覆盖 `any`、主机、CIDR、范围和 IP 组，并证明没有越界域名组入口。
- Playwright 覆盖创建、选择已有对象、快捷创建对象、格式错误、引用保护、保存、应用、失败和回读。
- 无文本遮挡、横向页面溢出、在线资源依赖、自由文本内部 ID、假选项或仅前端接受但后端无法执行的输入。
