# LY-Route 白皮书

## 产品主张

LY-Route 用同一套本地优先的控制面基础，构建两个有意隔离的设备产品。Gateway 负责路由型出口服务，Orchestrator 负责透明、策略驱动的服务链。这样的边界避免网关的大而全 schema 渗入编排器，使安装、升级、故障和运维预期保持确定。

## 出口网关

Gateway 面向分支和边缘出口，管理 LAN/WAN、主备/加权/五元组三种 WAN 组、路由/NAT、DNS/DHCP、订阅代理固定/最快节点、用户限速、内置智能 QoS、安全、遥测、审计、回滚和维护。代理逻辑 WAN 不得加入 WAN 组。LAN TCP/UDP 53 默认由本机接管；DNS 是独立首匹配策略轴，可固定选线，并优先于普通策略路由，DNS 应答关联流量在 TTL 内继承其线路。运行状态必须从实际执行配置的服务回读。

## 流量编排器

Orchestrator 具有独立 Linux 管理口和一个逻辑 LAN/WAN 转发路径。每个编排组严格由一个 `lan_facing` 和一个 `wan_facing` 逻辑端点构成，端点可由物理口或 bond 承载。有序策略先执行安全拒绝，再执行流量控制，最后选择 `via`、`direct` 或 `drop`。`via` 返回流量必须经过完全相同的服务实例并严格逆序；服务节点失效时默认 bypass，剩余链仍保持对称。

它不是第二种网关：NAT、DNS/DHCP、代理网关、域名对象、OAF/DPI/应用识别/上网行为审计、Bridge 产品模式、云管理、HA 和 VRRP 均不在其范围。

## 技术路线

Go 控制面校验产品专属意图，保存版本化状态，编译候选配置，以事务方式下发，校验实际状态，然后提交或回滚。共享选择器自动探测每张数据网卡，优先选择实测通过的最优 VPP 原生高性能候选；原生候选全部失败时才使用 VPP DPDK。整台设备全部活动数据接口统一采用最高共同合格等级。这是高性能回退，不是兼容性降级。两个等级都失败时管理面保持可访问，转发保持锁定并给出诊断，不使用 copy-mode 或 Linux 转发路径。

## 交付标准

只有 schema 或 UI 不代表完成。软件全功能验收必须覆盖 DNS/DHCP、路由/NAT、真实 PPPoE 拨号、WAN/代理故障、满载智能 QoS、安全/遥测、对称服务链、节点 bypass、浏览器和系统产物；发布证据还必须覆盖目标硬件、产品隔离，以及 x86_64/ARM64 的独立安装、升级和回滚。当前证据和后续工作分别见[实现状态盘点](implementation-status.md)与[工作计划](work-plan.md)。
