# `any` 边界与 ACL 双向修复说明

## 修复范围

本次修复统一网关安全策略中 `any` 和方向字段的语义，避免把不同类型的流量控制误当成同一种出站规则：

- NAT 的 `any` 仅匹配 LAN 发起的出站连接，SNAT 只从 LAN 进入、从 WAN 送出。
- DNS 透明劫持的 `any` 仅处理 LAN 终端发起的 TCP/UDP 53 请求，DNS 策略不会接管 WAN 入站流量。
- 端口映射继续保留外部入站和返回流量语义，外部源地址为 `any` 时只表示不限制来源。
- ACL 的地址 `any` 仍表示对应地址方向的全匹配；ACL 方向支持入站、出站和双向。

## 实现调整

- 策略解析保留 `both`，并兼容 `bidirectional`、`input_output`、`inbound_outbound` 与中文“双向”。
- VPP 不提供单个 `both` 接口挂载，因此双向 ACL 在控制面展开为同一规则的 input 与 output 两个挂载。
- ACL 更新、删除、回滚和生命周期清理均同时处理两个方向，避免残留旧挂载。
- 端口映射和默认 WAN 入站拒绝规则仍使用各自原有的入站路径。

## 验证

新增定向测试覆盖：

1. `both` 的 API 配置不会被解析成 input。
2. 安全代编译会生成 input/output 两个 ACL 组。
3. 普通 ACL 的 VPP 命令会同时生成 input/output 挂载命令。
4. input 与 output 单向规则不会被错误扩展为双向。

完整 VPP 测试包中另有两项历史断言失败：PPPoE 路径断言与旧源文件行数门槛，已单独记录，不属于本修复的回归。
