# 产品验收契约

验收以证据为准。当前实现见[实现状态盘点](implementation-status.md)，规范范围见[产品功能边界](product-functional-boundary.md)，剩余工作见[工作计划](work-plan.md)。

## 必须通过的门禁

1. **静态与单元门禁**：格式、lint、schema、后端单元/集成、前端单元、profile 隔离和 OpenAPI 契约。
2. **UI 门禁**：完成 U1/U2 设计系统迁移、产品专属菜单/路由、操作成功与失败、实际状态刷新、可访问性、桌面/平板/手机视口和视觉回归证据。
3. **配置门禁**：类型化 `any`、主机、CIDR、范围和适用对象引用经过保存、导出、导入、应用和回读语义不变；对象重命名/删除和坏输入行为确定。
4. **运行时门禁**：事务应用、回滚、重启对账、漂移检测，以及数据面锁定时管理面可访问。
5. **全功能包流门禁**：按[双产品全功能验收设计](container-network-validation.md)，逐项追踪所有产品功能。Gateway 必须覆盖默认 TCP/UDP 53 接管、DNS 固定线路及其高于 PBR 的 TTL 选路、DHCP、路由/NAT、PPPoE、三种 WAN 组、代理固定/最快节点、双层 QoS、安全和遥测；Orchestrator 必须覆盖物理/bond 逻辑端点、完整策略、对称服务链和节点失效默认 bypass。任一必测功能缺失、跳过或只有 mock 时不得宣布全功能验收合格。
6. **产物门禁**：x86_64/ARM64 全新安装、升级、回滚、卸载、清单、哈希、产品隔离和可复现性。
7. **硬件门禁**：整机最高共同合格等级、原生优先/DPDK 回退选择、吞吐、时延、丢包、CPU/内存开销、温度、重启恢复、回滚和不支持硬件的诊断。容器功能门禁不能替代硬件发布门禁，硬件暂缺也不能降低容器功能门禁。

## 专项验收阈值

- **DNS 权威优先级**：客户端直发任意外部 TCP/UDP 53 必须被本机接管；DNS 选 WAN A、PBR 选 WAN B 时，DNS 请求及 TTL 内关联业务流必须走 A；TTL 到期后才恢复 PBR。代理 DNS 必须证明请求本身进入代理。未命中或命中线路失效返回 NODATA，不回落到默认上游、低优先级规则或普通路由。
- **最快代理**：候选先通过代理协议可用性探测；主要排序指标为滚动 ping RTT。测试必须证明更优节点稳定切换、短时抖动不反复切换、当前节点失效后自动迁移新连接、恢复节点经连续成功后再参与排名。所有选择和切换都有时间、指标及原因。
- **智能 QoS**：分别记录空载和上下行满载时的 RTT、p95/p99 延迟、抖动、丢包、吞吐、主机/流公平性、CPU 和内存。阈值必须按目标速率/架构建立基线并锁定；不能只用“已启用 CAKE/SQM 类模块”作为通过证据。
- **节点 bypass**：节点失效后，失效节点不再收到新流，剩余正向链和回程链保持严格互逆；没有健康节点时流量 direct；恢复期间不得出现环路、单向链或半配置。

证据必须标明产品、架构、提交、产物哈希、拓扑、命令、预期、实际结果和保留日志。依赖未注册 CI Runner、未提供目标硬件或尚未执行真实包流的检查不得标记完成。
